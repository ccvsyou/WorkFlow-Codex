# FlowCodex 产品评估（产品视角）

- 评估日期：2026-10-20
- 评估对象：`main` 分支 v0.2.0（含一键体验改动，尚未部署到线上）
- 评估方法：产品定位、JTBD、激活/留存、交付闭环、可度量性与路线图；结合本地 Mock 全链路实测、线上实例（v0.1.7）与既有商业化评估
- 关联文档：[COMMERCIAL_READINESS.md](COMMERCIAL_READINESS.md)（商业化/安全/运维视角）

> 本报告是产品判断，不替代客户访谈。所有价格、转化率和返工率均为待验证假设，不是实测结论。

## 一、结论先行

**产品值得做，而且已经过了“只能演示”的阶段，进入“可以找 3-5 个设计伙伴做付费试点”的阶段。**

但当前卖点仍然偏“过程很完整”，而不是“结果明显更好”。下一阶段最重要的不是再加一个 Agent 阶段，而是补上两件事：

1. **最后一公里**：把隔离分支变成 PR/MR，让交付真正进入团队现有协作流。
2. **可度量**：让客户看得见返工率、人工介入次数、验证通过率和单次成本。

产品评分：**7.0 / 10**

|---|---:|---|

## 二、产品定义

### 一句话

**FlowCodex 是一个自托管的“需求到可验证交付”工作流 Agent：先把需求谈清楚，再把方案拆到可执行，最后在隔离环境里编码、审查、验证并交付。**

### 它不是什么

- 不是代码补全，不追求“打字更快”。
- 不是通用聊天机器人，不以对话轮次为产品单位。
- 不是全自动无人值守交付，人在关键节点仍然拍板。
- 不是多租户 SaaS，当前形态是单租户自托管。

### 用户雇佣它完成的工作（JTBD）

> 当我要把一个中等规模需求交给 AI 时，我想先确认它理解对了、改动范围可控、结果真的验证过，这样我才敢把它合并进主干。

这句话决定了产品的价值排序：

1. **敢合并** 比 **写得快** 更重要。
2. **过程可解释** 比 **一次生成很长** 更重要。
3. **失败可定位** 比 **永远成功** 更重要。

## 三、目标用户与场景

| 角色 | 典型场景 | 现在的替代方案 | 愿意付费的点 |
|---|---|---|---|
| 独立开发者 | 自己维护 1-3 个仓库，想用 AI 做完整小需求 | Cursor / Claude Code + 手工验收 | 少返工、过程留痕、知识可复用 |
| 2-10 人技术团队负责人 | 把 AI 引入团队，但担心质量与范围失控 | 口头规范 + Code Review | 统一门禁、可审计、隔离执行 |
| 外包/交付团队 | 多条小需求并行，需要稳定交付 | 人工排期 + 模板 | 单条需求的完整交付记录与证据 |
| 对数据敏感的组织 | 代码不能进第三方 SaaS | 自建脚本 + 内部平台 | 自托管、可换模型、数据留在本地 |

**不建议的首批用户**：资金/支付核心链路、大型跨仓库重构、强合规强审计企业、需要 DBA 审批的 schema 变更。

## 四、价值公式

```text
交付价值 = 需求澄清质量 × 方案可执行性 × 验证可信度
          − 人工返工 − 等待时间 − 理解成本
```

FlowCodex 的差异化不在第一项“生成”，而在后三项“减少返工、减少等待、减少理解成本”。因此产品叙事应始终围绕：

- **少返工**：访谈 + 可行性 + 方案门禁。
- **少污染**：独立 worktree + 范围约束。
- **可验证**：审查 + 验证命令 + 产物留痕。
- **可复用**：知识飞轮 + Obsidian 导出。

## 五、核心体验闭环与激活漏斗

### 现状闭环

```text
提交需求 → 需求访谈 → 可行性评分 → 技术方案 → 人工批准
        → 隔离编码 → 代码审查 → 验证 → 交付 → 知识蒸馏
```

### 首次体验（本次已补齐）

空状态提供“开始 10 分钟体验”：

1. 自动创建隔离示例 Git 仓库与示例项目。
2. 自动提交一条“完善 README”的示例需求。
3. 用户只需回答澄清问题、批准方案，即可看到完整交付。

本地 Mock 全链路实测（2026-10-20）：

| 指标 | 结果 |
|---|---|
| 示例仓库/项目/需求创建 | 成功 |
| 澄清问题数 | 2 |
| 方案步骤数 | 3 |
| 可行性总分 | 83 |
| 补丁应用 | 成功 |
| 审查结论 | pass |
| 验证命令 | 通过 |
| 知识沉淀 | 1 条 |
| 交付产物 | `docs/flowcodex-run.md` 可下载 |
| 端到端耗时（Mock） | 约 6 秒 |

> Mock 耗时只用于验证链路，真实模型单条运行约 3 分钟（见商业化评估中的 DeepSeek 样本）。

### 激活漏斗与指标

| 阶段 | 事件 | 目标 |
|---|---|---|
| 访问 | 打开工作台 | — |
| 激活第一步 | 点击“开始 10 分钟体验” | ≥ 40% 新访客 |
| 激活完成 | 首条示例运行 completed | ≥ 70% 启动者，且 ≤ 10 分钟 |
| 关键转化 | 接入自己的真实仓库 | ≥ 30% 完成示例者 |
| 首次真实价值 | 第一条真实需求 completed | ≥ 50% 接入者 |
| 留存 | 7 天内提交第二个需求 | ≥ 40% |
| 复用 | 知识被注入/采纳 | ≥ 30% 的运行 |

**北极星指标：每周通过验证的交付数（Verified Deliveries / week / active project）。**

**质量护栏**：人工介入次数、返工率、验证失败率、单次运行成本、平均交付时长。

## 六、产品评分依据

### 强项

1. **定位清楚**：一句话能说清“不是又一个 AI Coding”。
2. **门禁是真的**：访谈、可行性、方案批准、critical 阻塞、验证失败阻塞都不是装饰。
3. **隔离是真的**：补丁只进独立 worktree，主工作区不被污染。
4. **过程可见**：阶段轨、事件时间线、Spec、方案、补丁、审查、验证、知识都在同一页。
5. **知识有闭环**：前置注入、交付后蒸馏、TTL、置信度、反馈降级。
6. **中文体验完整**：界面、状态、错误提示、Mock 内容均已中文化。
7. **可部署**：Docker Compose + Caddy + 腾讯云轻量服务器已跑通。

### 弱项

1. **交付止于补丁**：没有 PR/MR，团队仍要手工搬运，价值感在最后一步断掉。
2. **接入后不可维护**：没有项目设置页，验证命令/允许路径改不了。
3. **成本不可见**：客户不知道一条需求花多少钱，不敢规模化使用。
4. **知识审核不完整**：`pending_review` 只能“反馈失真”，不能批准/驳回。
5. **历史不可检索**：运行多了以后找不到，缺筛选、搜索、分页。
6. **协作能力弱**：单 Token，无法区分谁批准、谁返工、谁导出。
7. **失败恢复弱**：阶段失败后只能返工，不能从当前阶段重试。

## 七、关键产品假设（必须先验证）

| 假设 | 内容 | 验证方式 | 通过标准 |
|---|---|---|---|
| H1 | AI 直接编码的返工率显著高于 FlowCodex | 10 条真实需求 A/B | 返工率下降 ≥ 30% |
| H2 | 团队愿为“过程门禁 + 自托管”付费 | 10 次客户访谈 + 3 份报价 | ≥ 3 家愿意付试点费 |
| H3 | 知识飞轮能被用户感知 | 知识命中率 + 满意度 | ≥ 30% 运行命中且满意度 ≥ 4/5 |
| H4 | 一键体验能转化为真实接入 | 漏斗埋点 | 示例完成 → 真实接入 ≥ 30% |
| H5 | 人工介入可控制在 2 次以内 | 运行数据统计 | 中位数 ≤ 2 次/需求 |

## 八、产品缺口与优先级

### P0：阻断真实使用（0-30 天）

1. **GitHub/GitLab PR 集成**：push 隔离分支、创建 PR/MR、回写 Spec/审查/验证结果、同步合并状态。
2. **项目设置 UI**：编辑仓库路径、验证命令、发布命令、允许路径、自动提交策略。
3. **成本与预算可见**：单次运行 token、预估费用、项目/月度汇总、超额告警。
4. **知识审核闭环**：`pending_review` 支持批准、驳回、编辑后入库。
5. **运行列表检索**：按项目、状态、时间筛选，支持搜索和分页。

### P1：提升复用与留存（31-60 天）

1. 运行完成/待决策的通知（邮件或 Webhook）。
2. 需求模板与验收标准检查表。
3. 逐文件 diff 浏览与行内评论。
4. 失败阶段重试，而不是整条返工。
5. 并发与队列可见性（当前单 Worker）。
6. 英文界面与国际化。

### P2：商业化与规模化（61-90 天）

1. 多用户、角色、审计日志。
2. 命令执行沙箱（资源/网络/文件系统限制）。
3. 多仓库/跨服务编排。
4. 插件化阶段与自定义门禁。
5. 托管 SaaS（前提是 Postgres + 队列 + 多租户 + 计费）。

## 十一、Go / No-Go

| 目标 | 结论 | 前置条件 |
|---|---|---|
| 找设计伙伴免费试点 | **可以，立即** | 一键体验 + 部署手册 |
| 收少量试点费 | **接近可以** | 补 License/条款/隐私政策 + 备份恢复 |
| 正式商业版本 | **不可以** | PR 集成、RBAC、审计、沙箱、成本控制 |
| 多租户 SaaS | **不可以** | Postgres、队列、租户隔离、计费、安全审计 |
